# xm-web

把内容组织为清爽、带个人气质、适合阅读技术长文的网站。

## 完整复现契约（先读）

本用户要求忠实复现原博客的文章阅读体验。开始建站或改造阅读界面之前，必须阅读 [完整功能与精确视觉规范](references/requirements.md)；实现前再看 [实际覆盖与缺项](references/implementation-status.md)。其中一至十五节为逐项验收，不得只凭这份入口摘要施工。该规范优先于旧版“更可读变体”的建议。

- 默认浅色，不需要暗色主题；基础 CSS → highlight.js → KaTeX → 站点 style.css，按此顺序一次性导入。
- 精确保留 72% / 14% / 14% 文章布局、三层背景渐变、16px/1.5 正文、.712em 代码字号、原色板、TOC 与悬浮按钮参数。compact 是另一模式，不能取代文章布局。
- 代码块/行内代码的公式默认也渲染；代码复制还原公式源码。文章只识别`$[公式]$`和`$$[公式]$$`，对于不是这样格式的需要自动转换。
- 完整文章包含目录/大纲、标题编号与搜索定位、彩虹括号、代码/公式/全文/选区四种复制、级联导航、环形进度与汉字+英文词统计。骨架没有的能力必须按参考组件接线并验收，不能静默略过。
- 第一 DOM 前消毒、异步竞态保护和素材授权边界继续保留。忠实复刻不恢复原安全缺陷。

## 开始时

- 修改现有站点：先看框架、主题、路由和内容模型，在已有结构中实现用户要的部分。React/Astro/Next 等项目沿用其栈，移植设计原则和渲染阶段，不强行重建为 Vue。
- 新站且用户未指定栈：可使用 `assets/starter/` 的 Vue 3 + TypeScript + Vite 骨架。先复制到新目录，或运行 `python scripts/scaffold.py <目标目录> --title "站点名称"`。脚本只接受不存在或为空的目录，不安装依赖、不部署。
- 用户只要 Markdown 美化：仅改阅读器和正文样式，不加入首页、工具站或专题栏目。
- 把用户的主题、受众、文章数据和可用图片带入；没有图片时保留骨架的 CSS 渐变，不擅自取得有版权的角色图。

## 视觉取舍

阅读 [references/design-system.md](references/design-system.md)。核心是天依蓝 `#66ccff`、阿绫红`#EE0000`、初音绿 `#39c5bb`、白色阅读面、低饱和渐变背景、圆角卡片和轻悬浮反馈。桌面长文为左大纲 / 中正文 / 右导航，窄屏折叠两侧。本次已指定忠实复刻：原色值、.712em 代码与布局尺寸就是默认要求；只有用户另行要求时才改为可读性变体。

首页需要有个人辨识度；正文需要安静、连续、足够宽但不横跨整个大屏。布局、字距、行高、段落层级和宽内容滚动先于装饰。不要将所有内容堆成同尺寸卡片，也不要用高强度动画覆盖阅读内容。

## Markdown 实现

涉及渲染、迁移、数学或复制时，阅读 [references/markdown-pipeline.md](references/markdown-pipeline.md)。所有文章、工具预览和嵌入文档必须共享一个编排入口，并分开处理内容取得、核心解析、DOM 装饰、页面布局与事件绑定。

骨架把 `renderMarkdownDocument()` 作为统一入口，保留原项目工具模块及其内部相对依赖。必须按约定顺序引入 GitHub Markdown、highlight.js、KaTeX 的样式，最后引入 `style.css`（统一装载全部站点覆盖）；美观公式依赖样式和字体，不能只安装 JS。`assets/starter/src/Reader.vue` 演示渲染结果的事件委托、异步竞态保护、失败状态和卸载清理。

保留的关键行为：
- 代码保护先于公式处理；公式原文可还原，Unicode 安全；忠实复现时 `codeFormulas` 默认 true，代码与行内代码公式也渲染；用户另有要求才关闭。
- h1–h6 唯一锚点与目录引用同一份数据，不能在侧栏重新生成另一套 ID。
- Mermaid 按需加载、严格安全模式、唯一图 ID、失败展示源码。
- 复制代码不带按钮文字，公式复制 LaTeX，全文复制原 Markdown；已渲染内容不能充当原始源码。
- HTML 清洗与 Mermaid 的边界明确；不将 `marked.parse()` 输出直接信任为安全 HTML。
- 资源路径支持部署 base，宽表格、长代码和公式只在局部横滚，不撑破页面。

## 交付与验收

新项目可分阶段先做首页与阅读页，但完成“同风格完整复现”前须补齐 requirements.md 中的搜索定位、工具规范化、选区复制、级联导航、进度环和字数等，不得把阶段骨架当成最终完整实现。PDF 或其它专题仍按需增加。骨架附有三篇虚构演示文章；交付用户站点时替换或明确标记演示，不冒充用户的真实内容。

按 [references/acceptance.md](references/acceptance.md) 检查桌面和窄屏、重复标题、公式/代码边界、坏图表、复制、安全样例、部署子路径和加载竞态。实际运行项目的类型检查/构建，并在可用时做浏览器行为验证。报告已测试和未测试项；不要仅凭安装包存在就声称功能已验证。

## 资源位置

- `assets/starter/`：可运行的轻量示例，不含 node_modules、原站正文、媒体或部署凭证。
- `scripts/scaffold.py`：跨平台复制骨架并替换站点名称，不覆盖已有项目。
- `assets/reference-components/`：原站阅读器、布局与控件的迁移参考，不是已接线完成的独立应用；先读其中的 ADAPTATION.md。
- `references/requirements.md`：完整逐项需求与精确 CSS/色表，必读。
- `references/implementation-status.md`：现有骨架覆盖、缺项和证据；不与要求混淆。
- `references/source-analysis.md`：原项目实证、架构取舍与需要改善的细节。
- `references/source-manifest.json`：原样保留文件的来源与校验值。

这些文件可整体复制到其他机器的个人 skills 目录；无需原项目仍然可访问。不要自动发布、安装全局依赖或覆盖用户已有目录。
