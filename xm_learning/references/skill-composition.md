# xm_learning：学习内容、测评与界面组合约定

自动读取两个依赖的当前版本，不要求用户再显式输入 `$xm_note` 或 `$xm_web`。本文不替代它们的完整要求。

## 1. 加载与资源定位

- 先完整读取同级 `../xm_note/SKILL.md`、`../xm_web/SKILL.md`；目录不相邻时在配置的 skill roots 中按名称定位。下述路径均相对于对应 skill，不是生成网站的目录。
- 较长学习讲解/答案解析：按 xm_note 指引读取 `references/style-evidence.md`；涉及证明、复杂 shape/复杂度、来源冲突、实现排错时，读取 `references/knowledge-quality.md` 的相关部分。
- 网站创建/界面改造：读取 xm_web 的 `references/requirements.md`、`references/design-system.md`、`references/implementation-status.md` 与 `references/acceptance.md`。涉及正文、公式或复制时读 `references/markdown-pipeline.md`；迁移参考组件前读 `assets/reference-components/ADAPTATION.md`。
- 不把两个 skill 填入 `agents/openai.yaml` 的 `dependencies.tools`：该字段是工具依赖，不是 skill 调用接口。自动组合由明确的读取与执行指令实现。
- 缺少依赖或引用资源时，说明缺项和受影响能力；可继续来源整理、内容建模等可靠部分，但不能宣称已完成对应风格复现。不自动安装、下载或覆盖其他 skill。

## 2. 职责与冲突处理

| 层次 | 主责 | 应用位置 |
| --- | --- | --- |
| xm_learning | 来源证据、学习路径、章节与知识点、题目质量、可视化准确性、学习进度与三界面互联 | 全站内容模型、Study / Testing / Answers |
| xm_note | 正确、专业、问题驱动的中文讲解，直觉、必要推导、shape 与具体例子 | Study 正文、答案推理与知识拓展、可视化注释 |
| xm_web | 浅色视觉、布局、Markdown/GFM、代码、数学、图表、目录、复制与阅读交互 | 全站主题、阅读组件、导航与公共控件 |

遵从用户明确范围和既有框架，再按职责组合；事实、证据与安全优先于风格。不要用博客首页替换学习系统，或为套主题删除测评功能。完整网站仍以学习、测验、答案三个主界面为核心；目录、知识图谱和工具入口置于合适的界面，不增加无关主系统。

只要求内容、单组件或单个界面时仍读取依赖以了解约定，但仅应用与交付物有关的部分。不因此搭整站、原地改写笔记或扩展范围。用户明确指定其他视觉/语言时遵从，并说明偏离默认风格的范围。

## 3. xm_note 的教学落点

- 围绕真实疑问推进：要解决什么问题、成立前提、机制/关键推导、如何理解结果。按需使用疑问式标题，不给每题套固定长模板。
- 保留本 skill 的新手可读、自包含背景、分选项分析、代码逐步推演与证据要求；不以“笔记感”为由删去关键推理。
- 首次出现的概念、符号、术语解释清楚；公式说明符号与含义；涉及张量时交代维度与轴，再用小例子检查。非数学/非张量主题不强加公式或 shape。
- Study 可展开完整学习线索；Answers 围绕题目解释并链接回相关段落，避免整章复读；Testing 题面保持中立和任务明确，不提前透露答案或解题提示。
- 题面复制、未作答题目导出、知识点预览与可视化测试模式不夹带隐藏答案。风格依赖不改变答案显示规则。

## 4. xm_web 的界面落点

- 默认仅浅色：天蓝 `#66CCFF`、青绿 `#39C5BB`、红 `#EE0000`、藕粉 `#ECAD9E`，白色阅读面与规定的三层浅渐变。精确颜色、透明度、尺寸、控件状态和 CSS 以 requirements.md 为准，不简化为近似蓝绿主题。
- 长文学习/解析页沿用桌面左大纲 14% / 白色正文 72% / 右侧导航区域 14%，窄屏按规范折叠；题目片段或嵌入文档使用 compact 规则，不把每道选择题硬套三栏长文。测试控件与交互可视化沿用同一色板、圆角、反馈。
- 原导航动作映射为 Study / Testing / Answers、章节、知识点和实际可用工具；不保留失效博客路由、虚构菜单或未请求的栏目。
- 共用 Markdown 编排入口，执行 GFM、单换行、消毒、highlight.js、KaTeX、代码内公式、Mermaid、目录/大纲/稳定锚点与编号、括号配对、资源路径/懒加载、源码复制等完整适用规范。标题锚点与章节/知识点稳定 ID 建立映射，不以渲染序号取代内容主键。
- CSS 顺序保持 GitHub Markdown → highlight.js GitHub → KaTeX → 站点覆盖；正文 16px/1.5、代码块 .712em 等忠实细节不擅自修改。不做暗色模式。
- 长文接入大纲、返回顶部/阅读进度、原 Markdown 全文复制、汉字逐字+英文按词统计。局部渲染不重复生成全局悬浮控件；题面复制只含允许公开的题目源码。
- 保留公式/代码源码、公式复制、代码复制、选区转 Markdown、Mermaid 失败源码兜底。动画以组件实现，不执行 Markdown 脚本；安全消毒边界和异步竞态清理不因复刻而省略。
- `assets/starter` 只是可运行骨架。先查 implementation-status.md，按范围补齐搜索定位、选区复制、级联导航、进度环、字数和 compact 等缺项；参考组件存在不等于已接线/已测试。不擅自复制原站文章、插画和用户图片。

## 5. 集成验收

在原有内容、来源、题目、可视化与 Markdown 检查之外，确认：

- 已读取两个完整入口及相关规范；使用已安装资源，不依赖原博客或机器专有路径。
- 同章可由 Study 进入测验，再由 Answers 返回知识点；稳定标识、进度与三个主界面保留。
- 抽查学习讲解与答案解析是否真正交代问题、前提、机制/推导和例子/结果，而非仅替换标题或配色。
- 三个界面的公式、代码、表格、引用、复制和主题一致；题面/题目复制不泄露未显示答案。
- 按 xm_web acceptance.md 检查桌面/窄屏、局部横滚、公式代码边界、重复标题、坏图表、复制、安全、子路径和加载竞态。仅将不涉及的行为标为不适用，不能将未实现项写成通过。
- 运行实际项目提供的类型检查、构建与可用浏览器测试；说明执行情况及缺项。交付报告简述三项 skill 的职责与落地结果，不声称未运行的测试已通过。
